# Tasks — visit-memory (агент помнит, куда ходил, а не только где оказался)

**Просьба владельца:** «нужно исправить известные баги и дыры и попробовать на других сайтах
прогнать». Хвосты были записаны словами — правки выбраны **замером журнала**, а не списком из
памяти. Журнал: [doc 26 § T-3l](../../docs/26-real-site-trials.md).

## Замер: чем формулировка хвоста отличалась от факта

- [x] **V1** хвост звучал «анти-залипание сработало не полностью» → уводил в
      `_repeats_too_often`, где всё исправно. SQL по `data/runs/app.db` (125 прогонов) показал
      **четыре** прогона с повторной навигацией и **пустые** `contract_violations`: правило
      G-H3 не срабатывало вовсе.
- [x] **V2** причина одна на все четыре — **редирект**: в `visited` кладётся адрес ПОСЛЕ
      редиректа, запрошенный URL — никогда. `sports.ru`: 3 захода на одну страницу из 8 шагов
      бюджета; `lenta.ru/archive` → `/2026/08/03` в трёх прогонах подряд.
- [x] **V3** второй источник того же класса — цель, до которой **не дошли** (две неудачных
      `goto`, offsite-редирект, robots): страницы нет, в `visited` не попадает ничего,
      кандидат остаётся в очереди.

## Правки (тест вперёд кода — характеризация падала до правки)

- [x] **V4** `RunState.attempted` + свойство `seen`; `remember(snapshot, requested_url=…)`
      кладёт алиас редиректа в `attempted`.
- [x] **V5** `ActionContext.attempted`, правило `url_not_visited` смотрит оба множества
      (doc 13 v0.10). Очередь кандидатов фильтруется по `seen`.
- [x] **V6** **граница закреплена тестом**: алиас нельзя досыпать в `visited` — на нём бюджет
      страниц (G-H1), и каждый редирект съедал бы страницу лимита. Тест падает на «наивной»
      починке.
- [x] **V7** алиасы пишутся в `metadata.redirect_aliases` и **исключаются** из
      `unreached_urls`: иначе приписка «не удалось открыть» назвала бы страницу, которая
      прочитана — то есть агент занизил бы собственный результат.
- [x] **V8** `word_count` считает код по **полному** тексту (`PageSnapshot.text_words`), а не
      берёт число модели: на живом прогоне она объявила 1380 слов при вдвое большем тексте, и
      это число идёт прямо в сравнение полноты (doc 05 v0.5).
- [x] **V9** тихие потери `article` получили след: чужой URL → запись в `not_found` с
      причиной; блок, не прошедший схему → `llm_stats.dropped_blocks`.
- [x] **V10** докстрока `_merge` описывала `MAX_PER_SECTION`, которого в функции никогда не
      было (попала не в ту функцию в поставке `sitemap-index`) — убрана.
- [x] **V11** гейты: 420 тестов, ruff, format, mypy strict, размер модулей (`loop.py` вышел за
      500 LOC → анти-залипание перенесено в `interaction.py`, к своим лимитам).

## Справочные разделы — знать и применять (замечание владельца 07.08)

      SparkFun условия доставки лежат именно на `/support`. Причина структурная: слуги дают

## Немецкая вертикаль — «ультра боевой режим» (T-3p, 07.08)

- [x] **V34** отбор пробами подтвердил правку блокеров **на живом сайте**: `kochbar.de`
      отдаёт 403 → статус `error` (раньше было бы `ok` и страница шла бы в синтез).
- [x] **V35** **дыра найдена разбором задачи ДО прогона**: значимое слово искалось классом
      `[a-zа-яё]`, и буквы вне двух алфавитов работали разделителями —

- [x] **V36** немецкие служебные слова в стоп-листе: `Seite` из формулировки совпадала бы с

- [x] **V37** контроль: русский и английский замеры **без изменений**, немецкая задача

- [x] **V39** живой прогон немецких сайтов: **ноль повторов**, все три дошли до руководств

- [x] **V40** **косяк:** интент был `generic`, хотя задача — явный поиск статьи. Словарь

- [x] **V38** ✅ **закрыт:** страница без текста **и** без ссылок получает `error`. Скриншот
