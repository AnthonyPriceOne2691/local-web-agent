## Зачем поставка

Кейс поставил владелец: три сайта из выдачи со статьями про ставки на футбол, агент должен
найти статью на каждом и сравнить. Это замыкает круг с фикстурами — UC-2 построен ровно на
этой задаче, только теперь на настоящем вебе. Базовая линия: **0 статей из 3** с ответом
«статей нет», при том что статьи там есть (эталон из выдачи, 15–20 k символов каждая).

## Что сделано и чем это проверено

| Испытание | Способ проверки | Итог |
|---|---|---|
| T-3d | живой прогон + офлайн-оракул | найдена и починена главная причина: **агент не видел содержимого страницы** — лимит ссылок отбирал по позиции в DOM |
| T-3e | офлайн-замер цепочки (8 страниц на диск, без сети и модели) | **правка T-3d проверялась на хопе 2, а прогон умирал на хопе 1**; найден дефект штрафа по имени хоста |
| T-3f | живой прогон, решение владельца «гнать как есть» | **0 статей из 3 — как в базовой линии**; маршрут изменился на записи вместо разделов; найден дефект честности итогового ответа |

## Починено с тестами

1. **Лимит ссылок резал по позиции в DOM** (T-3d-1). Замер на `sports.ru/betting/stavochnaya-wiki`
   (420 ссылок): при лимите 40 отброшено 50 из 52 тематических, при лимите 300 — всё равно
   мимо, потому что статьи лежат на позициях #345–#351. Вывод, который и есть находка:
   **любое фиксированное N режет контент**, позиция содержимого у каждого сайта своя.
   Лимит стал предохранителем по памяти (1200), отбирает счёт очереди.
2. **Стимулы формулы вели от ответа** (T-3d-2): `slug`/`shallow` достаются спискам, ссылке
   на статью не начислялось ничего. Итоговое правило — тема главная (20), форма разрешает
   ничью (+8 при теме, +4 без), нечитаемая ссылка получает −4 (doc 21 v0.8).
3. **Штраф ловился в имени хоста** (T-3e-1): `/legal` совпадает внутри `//legalbet.ru`, и
   каждая ссылка сайта-обзорника теряла 8 очков как юридическая страница; так же `//cartier`
   на `/cart` и `//logincorp` на `/login`. Тесты — `test_penalties_do_not_fire_on_the_host_name`
   с обратным контролем на настоящие `/privacy`, `/cart`, `/account/login`.
   **Чего не лечит:** порядок очереди на этих сайтах не сдвинулся ни на одной из 8 страниц —
   штраф был одинаков для всех ссылок хоста.
4. **Оговорка про неполный обход не доходила до итогового ответа** (T-3f-2). Обход на всех
   трёх сайтах обрезало `G-H2` на **3 страницах из 12**; `note_limits` дописал оговорку в
   разбор каждого сайта, но в сообщении сравнения — единственном, которое читает человек, —
   стояло «на legalbet.ru и sports.ru вообще не найдены материалы по теме», и оценки 20/10/5
   это закрепляли. Своё ограничение подано как свойство сайта. Теперь строка `reading_cut`
   добавляется **кодом** по тому же признаку, что per-site приписка (doc 24 v0.13).
   Тест + негативный контроль.

## Главный результат — и он отрицательный

Критерий был объявлен заранее: **найдена ли статья на каждом сайте**. Живой прогон T-3f:
**0 из 3**, как в базовой линии. Правка изменила поведение, но не исход:

| Сайт | базовая линия | T-3f |
|---|---|---|
| `legalbet.ru` | `/news` → `/bonus/sets/…` → `/bukmekerskye-kontory` | прогноз на теннисный Мастерс → «как букмекеры рассчитывают ставки» |
| `www.sports.ru` | `/betting` → `/betting/news` → `/football` | два футбольных блога |
| `www.championat.com` | превью матча → `/football` → `/guide` | `/news/bets/1.html` → превью матча |

Причина названа замером T-3e **до** прогона: с корня путь к обучающему разделу в top-10 не
попадает (`legalbet` хаб #20 из 285 ссылок, `sports.ru` вики #134 из 731 с пустым текстом
ссылки, `championat` #10). Предсказание «0–1 статья из 3» подтвердилось.

## Мои ошибки этой поставки (записаны намеренно)

1. **Правка 40 → 300 была тем же позиционным отбором** с другим числом.
2. **Первая версия весов дала форме URL больше веса, чем теме** — агента потянуло в
   нетематические записи (турниры, теги, видео); владелец описал это как «тянет влево».
3. **Оракул стоял не на том шаге:** проверял хоп 2 (счёт 12 → 34) при том, что прогон
   умирал на хопе 1. Зелёный оракул не значил ничего.
4. **Две ошибки внутри самого оракула**, найденные до выводов: полный список считался с
   `on_homepage=True` на разделах; не было SPA-fallback — `sports.ru/betting/` давал 0
   ссылок вместо 823.
5. **Замер T-3f контаминирован глубиной:** базовая линия шла с `max_depth 3`, повтор с `2`
   (у CLI `research` флага нет, глубина приходит из процесса API). Обход встал на 3
   страницах против 4. Вывод «правка исход не изменила» — направленный, не измеренный.

## Оракулы и негативные контроли

- **Shape:** ruff (`backend cli scripts`), ruff format, `check_module_size.py`, import-linter,
  21 pre-commit хук — все зелёные на каждом коммите.
- **Behavior:** 384 теста (было 380), `mypy --strict` 93 модуля. Оба новых теста писались
  **до** правки и падали на старом коде — негативный контроль зафиксирован.
- **Живой прогон:** T-3f, сессия `728bbe9bc866`, 28.4 мин; телеметрия по стадиям снята из БД.
- **Офлайн-оракул:** 8 страниц трёх сайтов сняты на диск, очередь считается детерминированно
  без сети и модели (нужно потому, что тоннель роняет треть загрузок).

## Что осталось незакрытым (перенесено, не потеряно)

- **Хоп 1 не починен** — узкое место названо дважды (офлайн и живьём). Решение владельца:
  чинить признак «обучающий жанр» против «промо», затем один живой прогон при равной глубине.
- Блокер прогонов — **сеть машины**: VPN-тоннель даёт стойки 16–30 s на трети загрузок
  любого хоста; владелец решил гнать как есть, числа времени этим зашумлены.
- `--max-depth` у CLI `research` нет: глубина приходит из процесса API и в ответе не видна.
- Ни один сайт не дал `article` при интенте `content_search` (`article_candidates_considered`
  пуст) — не разобрано.
- Остаток 206–270 s на сайт **не размечен** и сознательно не приписан стадии.
- `ReadTimeout`/`ReadError` от Ollama маппятся в «сайт не ответил» — причина не отличает
  локальную модель от сайта.
