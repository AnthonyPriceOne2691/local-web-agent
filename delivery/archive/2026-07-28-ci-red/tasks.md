# Tasks

## Mini-spec (class S, §2.2)

**Проблема.** CI красный с самого первого прогона (6/6), но в STATUS стояло
`ci-oracles: tooling`, и две поставки были закрыты как done. То есть
неподделываемого слоя (Delivery §10.4) у контура фактически не было.

Три причины, установленные по логам `gh run view`:

| # | Симптом | Причина |
|---|---|---|
| 1 | `quality / gates` падает на первом же шаге | mypy 2.3.0 даёт `INTERNAL ERROR` в CI (Python 3.12; локально 3.14 — зелёно). pre-commit передаёт 84 файла **пачками**: первая партия «Success: 42 files», вторая — краш. Из-за `-e` шаг обрывает джобу, и 4 следующих шага (gate-coverage, secrets, baseline-ratchet, diff-coverage) **не выполнялись ни разу** |
| 2 | `main-guard` красный на каждом push, 3 открытых issue | он гоняет `pre-commit run --all-files`, не установив ни `backend/.venv`, ни `node_modules` — хуки, зовущие `backend/.venv/bin/*` и `npx --no-install`, не могут работать по построению. Шум вместо сигнала |
| 3 | «done при красном CI» прошло незамеченным | в harness нет oracle на **статус CI**. `merge_guard` проверяет слитое состояние локальными версиями (Python 3.14), поэтому расхождение с CI-окружением он не поймает в принципе |

**Готово, когда.** Прогон `quality` на main зелёный целиком (все шаги `gates` +
`delivery`), `main-guard` не создаёт ложных issue, а попытка мержа при красном CI
механически блокируется. `ci-oracles` возвращается в `tooling` по факту.

**Вне scope.** Ускорение CI, кэши, матрица версий, playwright-браузеры в CI.
