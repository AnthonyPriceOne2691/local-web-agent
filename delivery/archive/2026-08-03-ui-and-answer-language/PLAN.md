# PLAN — ui-and-english-output

Порядок: сначала то, что врёт пользователю (язык и служебный текст), потом то, что
мешает читать (раскрытие, контраст), потом однородность движения.

## Шаг 1 — язык вывода и служебный текст ✅

Промпты: «write in the language of the TASK» → «write everything in English» с явным
исключением для verbatim-цитат. Формулировки: `humanize_detail` переводит техническую
причину в человеческую, нераспознанное отбрасывает. Тесты — на оба.

## Шаг 2 — правки интерфейса по списку ✅

`gap` у списка чатов · статусные чернила `--status-*-ink` · раскрытие карточки сайта
(`reveal` + `clamp-soft`) · плюс фигурой · подсказка ввода отдельным элементом ·
числа таблицы по центру и `tabular-nums`.

## Шаг 3 — движение как система ✅

Одна кривая (`cubic-bezier(0.32, 0.72, 0, 1)`) и один набор утилит: `rise-in`
(появление), `press` (нажатие), `reveal` (раскрытие), `animate-breathe` (живой
индикатор вместо тревожного `animate-pulse`). `prefers-reduced-motion` снимает
анимацию, не поведение.

## Шаг 4 — доки

16 (язык вывода) · 17 (UI и движение) · 26 (T-3c переклассифицирован из успеха в
дефект, с причиной) · индекс.

## Шаг 5 — проверка

Гейты + живой прогон с русской задачей по русским сайтам: ответ должен быть
английским, служебного текста быть не должно.

## Чего в плане нет

- Переписывания дизайн-языка: правки из списка, а не новая тема.
- Автотестов UI: их нет и в этой поставке не появляется — сказано в SPEC.
- Attended-испытаний (T-2a, T-1) — они ждут владельца отдельной поставкой.
