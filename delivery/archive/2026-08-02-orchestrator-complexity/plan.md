# Plan: сложность ядра оркестратора (class M)

К спеке `spec.md` (подписана 2026-08-02). Порядок шагов важен: сначала
дешёвое и изолированное, `run()` — последним, когда приём уже отработан.

## Approach

**Состояние — объект, а не десять аргументов.** `run()` тащит через весь цикл
`visited`, `hops`, `snapshots`, `homepage`, `current`, `next_url`, `extract_streak`,
`stale_pages`, `repeats`, `seen_relevant`, `just_visited`, `step_index`. Разбор без
общего состояния превратится в функции с 10+ параметрами (и упрётся в `PLR0913`).
Поэтому вводится мутируемый `RunState` (dataclass в `orchestrator/state.py`), а шаги
получают `(state, ctx)`.

**Шаг возвращает решение, а не «просто выполняется».** Внутри цикла сейчас 12 `break`
и 6 `continue`; если вынести шаги «как есть», управление потеряется. Каждый шаг
возвращает `StepOutcome`: `CONTINUE` (следующая итерация), `PROCEED` (идём дальше по
той же итерации), `STOP` (выход из цикла) — цикл остаётся плоским и читаемым.

**Дифф — перестановка и извлечение.** Ни одно условие не переписывается «заодно».
Если по дороге найдётся настоящий дефект — он выносится отдельным коммитом с тестом и
называется в verify-report, а не прячется внутри рефакторинга.

## Шаги (каждый — отдельный коммит, гейты зелёные после каждого)

1. **Тесты инвариантов (до кода).** cancel на трёх границах; G-S1; attended-пауза на
   `captcha` и `login_wall`; handoff → только фиксация исхода; анти-залипание для
   `click`/`fill`/`fill_form`; `extract_streak ≥ 2`; исключение в середине → `failed`
   с сохранением записи. Прогнать на **текущем** коде — обязаны быть зелёными.
   Отдельно поднять покрытие `candidate_queue` до ≥ 85 % (сейчас 74 %, не покрыты
   ровно ветки, которые буду двигать).
2. **Мелкие функции** (`select_vision_jobs`, `build_report`, `validate`,
   `plan_validated`) — по одной, каждая: извлечь 2–3 именованных шага, снять
   заморозку, прогнать тесты. Здесь отрабатывается приём и видно, что тесты ловят.
3. **`build_candidates`** — источники кандидатов (ссылки страницы, slug-пробы,
   sitemap, probe-links) в отдельные функции-сборщики, общий скоринг остаётся один.
4. **`runner.run_message` / `_run_llm_plan`** — разделить «разобрать план» и
   «исполнить шаг плана»; tool-ноты и M-H* остаются на месте.
5. **`run()`** — последним, в четыре шага:
   `_prepare()` (валидация конфига, warmup, robots, rate, пробы, sitemap, профиль,
   старт браузера) → `_observe_step()` (navigate+observe, блокеры, attended) →
   `_plan_step()` (кандидаты, G-S1, `plan_validated`, запись шага) → `_act_step()`
   (диспетч по действию, тиры, анти-залипание) → `_finalize()` (vision, синтез,
   валидация результата, отчёт).
6. **Снять заморозки** из `backend/pyproject.toml` (все семь), прогнать
   `ruff --isolated --select C901,PLR0912,PLR0915` по `backend/app` — пусто.
7. **Продуктовый прогон** (eval-smoke): UC-2 на фикстурах, Tier 3 attended на 8908,
   одна real-site сессия из Chat UI. Сравнение с записанными прогонами по существу
   (победитель, факты, доли стадий), а не «отработало без ошибок».

## Stack / boundaries

- Слои не меняются: `orchestrator` не начинает импортировать `contracts`/`web`
  (`lint-imports` это ловит).
- `loop.py` держать ≤ 500 LOC — новые модули (`state.py`, шаги) выносятся рядом,
  как уже сделано с `decide.py`, `discovery.py`, `capture.py`, `interaction.py`.
- Промпты и словари не трогаются вовсе.

## Risks

| Риск | Смягчение |
|---|---|
| Потерянная ветка в `run()` (12 `break`) | `StepOutcome` + тесты шага 1 до рефакторинга |
| Изменение порядка проверок (cancel, handoff-перед-submit) | отдельные тесты именно на порядок; в verify-report — таблица «инвариант → тест» |
| Тихая правка условия под видом извлечения | правило диффа: только перестановка; исключения называются поимённо |
| Раздувание сигнатур (`PLR0913`) | `RunState` + `ctx`, а не длинные списки параметров |
| Прогон «зелёный, но другой» | сравнение с **записанными** прогонами по существу ответа |
| Модели на M5 Air (14B) | продуктовый прогон запускаю только по слову владельца, после — выгружаю |

## Оценка объёма и circuit breakers

Ожидаю ~15–20 файлов и 600–900 строк нетто-диффа: это близко к порогу §3.4
(25 файлов / 800 LOC). Если план упрётся в breaker — **дробим на две поставки**
(мелкие функции + `runner`; отдельно `run()`), а не выписываем waiver.
