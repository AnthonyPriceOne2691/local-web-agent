# Eval smoke — real-site-trials (class M, §6.2 обязателен)

Продуктовый oracle этой поставки — **сами испытания на реальных сайтах**: правки родились
из живых прогонов, и доказываются они прогонами же, а не только юнитами. Проверяем не
«отработало без ошибок», а конкретное поведение до и после каждой правки.

## E1. Чужая аналитика больше не уносит страницу (T-3a-1)

- [x] ✅ до правки: `simonwillison.net` и `martinfowler.com` — по **0 страниц**, run
      `failed`, `Page.goto: Timeout 30000ms exceeded`; сессия потратила 46 % времени
      впустую, стадия `compare` не запускалась вовсе.
- [x] ✅ причина установлена замером, а не догадкой: `commit` 0.7 s против
      DOMContentLoaded 31.0 s / 30.7 s, у контрольного `blog.rust-lang.org` — 0.8 s.
      Виновники названы поимённо: `static.cloudflareinsights.com`, `cloud.umami.is`
      (`ERR_TIMED_OUT` 30.2 s / 30.0 s).
- [x] ✅ первая гипотеза («блокирующий скрипт в `<head>`») **опровергнута**: у упавших
      сайтов таких скриптов ноль, у сработавшего — один. Настоящая причина: DOMContentLoaded
      ждёт и `defer`-скриптов.
- [x] ✅ после правки: `simonwillison.net` — **3 страницы**, run `completed`.
- [x] ✅ сессия целиком: **3 сайта из 3**, сравнение прошло, победитель `simonwillison.net`
      (95) с обоснованием про статью о релизе `condense-json 1.0`.

## E2. Граница знания видна в ответе (T-3a-2, T-3c-1)

- [x] ✅ до правки: факт `confidence: high` «на сайте **нет** подробного разбора релизов» —
      про блог Rust, где анонсы релизов основной жанр; статья лежала на третьем хопе при
      `max_depth: 2`.
- [x] ✅ промпт-запрет проверен и **не оправдал доверия**: послушался на 1 сайте из 2
      (`martinfowler.com` — «not reached fully» + `low`; `blog.rust-lang.org` — снова
      отсутствие с `high`).
- [x] ✅ после правки кодом: в живом прогоне `habr.com` ответ содержит «Reading was cut
      short by the agent's own limits, not by the site lacking content».
- [x] ✅ второй повод (оборванный обход) закрыт: `early_stop` G-S1 теперь тоже попадает в
      приписку — нашёлся на прогоне, где нарушений было ноль.

## E3. SPA-каталог читается, ложный блокер снят (T-2b-1)

Одна задача, один сайт, до и после правки:

| | до | после |
|---|---|---|
| статус | `blocked` (`login_wall`) | ✅ `completed` |
| страниц | 1 | 2 |
| фактов | 1 | **10** |
| цены | «цены не указаны» (`not_found`) | `$320`…`$820`, цитаты из DOM |

- [x] ✅ SPA-fallback оказался **исправен** — контент, которого в сыром HTML 673 символа,
      извлечён из отрендеренного DOM. Ломал его ложный блокер, а не сам механизм.
- [x] ✅ негативный контроль: страница с **видимым** полем пароля и URL `/login`
      по-прежнему дают `login_wall`.

## E5. Настоящий A/B по глубине (T-3a-3)

- [x] ✅ первый A/B **не измерял ничего** — оба плеча шли на одной глубине, потому что
      `max_depth` не доходил до research-сессий. Совпадение плеч распознано как сигнал
      проверить ручку, а не как вывод «разницы нет».
- [x] ✅ после починки: глубина 3 снимает стену у 2 сайтов из 3 (`blog.rust-lang.org`
      3 → **8 страниц**, 3 факта, G-H2 исчез) за **+53 %** времени; у `martinfowler.com`
      стена переносится на хоп глубже. Вывод: фиксированной «правильной» глубины нет.
- [x] ✅ отдельно зафиксировано, что оценки сравнения для таких выводов не годятся: у
      одного сайта при одинаковой конфигурации выходило 15 / 15 / 40 / 10.

## E6. Медленный сайт: честный предел (T-3b-1)

- [x] ✅ `OBSERVE_JS` падал `TypeError: reading 'innerText' of null` — `document.body`
      разыменовывался без проверки; замер: тело появляется на **32.1 s** у `habr.com`
      против 2.1 s у `lenta.ru`, заблокированных трекеров ноль (прошлая правка не виновата).
- [x] ✅ сказано прямо: на старой стратегии habr тоже не читался бы (30 s < 32.1 s) —
      правка убирает падение, а не делает сайт быстрее.
- [x] ✅ с `LWA_PAGE_TIMEOUT_MS=45000` habr читается (`completed`, 3 страницы), цена —
      ~33 s на страницу.

## Что этот oracle НЕ проверяет

- **Attended-пути** (T-2a login-wall, T-1 Tier 2 submit и Tier 3 handoff) — переносятся в
  следующую поставку: нужен человек.
- **Умный обход страниц-списков.** Ответ стал честно говорить, что чтение обрывалось, но
  G-S1 по-прежнему останавливается на странице со списком статей. Это записано в хвосты, а
  не выдаётся за исправленное.
- **`lenta.ru` → `not_found`** при двух прочитанных страницах — не разобрано.
