## Хвосты, добавленные испытаниями T-3 (doc 26)

- **`Settings.max_depth` не действует на прямом пути `POST /runs`** — тело запроса
  авторитетно, `RunConfig` берёт дефолт схемы, у CLI `crawl` флага глубины нет вовсе.
  Research-сессии починены, одиночный crawl нет. Нужен `--max-depth` в CLI либо дефолт из
  настроек в API (T-3b-2).
- **Оценка ссылок на страницах-списках** — самое дорогое из найденного. G-S1 остановил
  обход на `blog.rust-lang.org/releases` (список анонсов релизов) как на «неинтересной»
  странице, а `ria.ru` трижды предлагал `/science` вне очереди кандидатов (`I-H6`,
  без recovery). Ответ теперь честно говорит, что чтение обрывалось, но обход умнее не
  стал. Лечится в doc 21, только с замером (T-3c-1, T-3b-3).
- **`lenta.ru` → `not_found` при двух прочитанных страницах** — не разобрано, записано.
- **Медленные сайты не проходят дефолтный бюджет:** у `habr.com` тело документа
  появляется на 32.1 s при `page_timeout_ms` 30000. С 45 s читается, но ~33 s на
  страницу. Возможно, стоит поднять дефолт — только с замером на быстрых сайтах, чтобы
  не платить ожиданием там, где его не нужно.
- **Блокировка трекеров ускорила обход** (20.2 s → 5.7 s на сайте), но список хостов
  теперь надо поддерживать — это принятая цена, названная в `data/browser/tracker_hosts.yaml`.

## Хвосты (перенесены, не потеряны)

- **`think:false` без схемы на `compare`** — единственная измеримая цель по скорости:
  стадия весит 36–41 % реальной сессии, 81 % её выхода — мысли. Входы для A/B в БД,
  скрипт замера воспроизводимости написан (`compare_variance`-подход).
- **Победитель при близких оценках зависит от формулировки задачи** (с «(getting
  started)» победил astro 95>85, без этих слов — 11ty 82>80). Детерминизм стадии это
  не лечит; думать про формулировку задачи и про показ «примерно равны» в UI.
- Язык narrative: re-compare отвечает по-английски на русский вопрос.
- `I-H6` на реальных доках: top-10 кандидатов против сотен ссылок в сайдбаре (doc 21).
  На последнем прогоне не всплывал — но задача была узкая.
- `article.word_count` модель заполняет неверно (14 при статье на ~400 слов).
- Cooldown 30 s при N ≥ 4 — на реальном прогоне 0.7 % сессии; только с замером.
- Cancel во время attended-паузы не прерывает мгновенно.
- **Сверка версий доков держится на внимании** — оракул этой поставки живёт в
  scratchpad, в репозиторий не вынесен (граница «только доки»). Именно так инвариант и
  сломался: тихо, на шесть поставок. Предложение владельцу — вынести в
  `scripts/check_docs_index.py` + pre-commit/CI отдельной поставкой класса S (цена
  входа: mypy strict, ruff, строка в `check_gate_coverage.sh`).
- **`loop.py` — 497 LOC при лимите 500**: запаса почти нет, следующий вынос понадобится
  при первой же правке стадий.
- Длительность шагов `SYNTHESIZE` не сохраняется — разложение сессии по стадиям
  приходится считать остатком; мешает честному замеру синтеза.
