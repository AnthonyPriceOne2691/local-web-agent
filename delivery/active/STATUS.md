## Контекст поставки

**Приоритет выбран владельцем (01.08): правка хука `protect_main`.**

Хук даёт ложное срабатывание на **составных** командах: правило матчит всю строку с
`re.DOTALL`, поэтому флаг из одной команды складывается со словом `main` из другой —
пуш ветки рядом с `pkill -f "uvicorn app.main:app"` читается как переписывание
истории. За одну сессию сработало трижды.

Решение: разбирать команду по разделителям (`&&`, `||`, `;`, `|`, перевод строки) и
проверять **каждый сегмент отдельно**; плюс `scripts/hooks/test_protect_main.py`, где
половина кейсов — «должен **пропустить**» (обычный пуш `main`, пуш ветки, перезапись
не-`main`, слово `main` в соседней команде, регрессия с `pkill -f`), а вторая —
«должен **заблокировать**» (force-push в main, удаление main на remote,
`reset --hard origin/main`). Опасные строки в тестах собирать из частей-констант,
иначе сам файл не пройдёт хук, когда его содержимое попадёт в командную строку.

Почему это важно: ложное срабатывание вреднее пропуска — цена обхода нулевая
(достаточно разбить команду на две), и хук перестаёт защищать по-настоящему.

   narrative в compare-промпте (re-compare отвечает по-английски на русский вопрос).
2. **`compare` без схемы** — единственная измеримая цель по скорости на реальных
   сайтах (36 % сессии); входы для A/B уже в БД.
3. **Сложность функций** (`C901`/`PLR09xx`, 10 модулей) — последний пункт долга гейтов.
4. **Открытый вопрос канона по robots** — владелец считает, что при работе «как будто
