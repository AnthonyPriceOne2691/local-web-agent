## Mini-spec (class S, §2.2) — приоритет подтверждён 2026-07-31

**Проблема.** Основной сценарий — несколько сайтов за одно сообщение. `synth-speed`
ускорила синтез одного сайта только на извлекающих интентах; на `content_search`
(типичном для этого сценария) канон сохранён, потому что быстрый путь оказался
бимодальным. Значит остаток длительности сессии лежит в двух местах, ни одно из
которых не измерялось.

**Что известно из предыдущих замеров** (переиспользовать, не мерить заново):

- 87–97 % времени синтеза — генерация; вход стоит 3–7 s. Урезание входа не ускоряет.
- Выходные токены воспроизводимы до единицы, wall-time шумит ±25 % → судить по токенам.
- Число фактов не годится как критерий качества (сверять ключи и значения).
- `qwen3:8b` на синтезе не быстрее 14b (пишет больше токенов).

**Открытые вопросы (нужен ответ до implement).**

1. `compare`: сколько он реально стоит в сессии на 3–4 сайта и какая доля выхода —
   рассуждение? Телеметрия для этого уже есть (`thinking_chars`/`content_chars`).
2. Cooldown 30 s при N≥4 — он про троттлинг fanless M5. Насколько он нужен сейчас,
   при том что синтез на извлечении стал втрое дешевле по токенам? Снимать его
   можно только с замером температуры/скорости на 6–10 сайтах, иначе «ускорение»
   обернётся деградацией на длинной сессии.
3. Перекрытие обхода и синтеза: GPU всё равно один, выигрыш ограничен сетевой
   частью обхода. Стоит ли вообще, или это сложность без эффекта?

### A/B compare (входы взяты из проведённой сессии, обход не повторялся)

| Режим | Результат |
|---|---|
| канон | 148.4 s, 1662 ток., мысли 49 %, narrative 600 симв., winner 8901, порядок 95 > 70 > 50 > 0, 5 размерностей |
| `think:false` + схема | **таймаут > 300 s** |
| то же + бюджет narrative | **таймаут > 300 s** |

**Схема для compare непригодна в текущем виде** — и причина не в рассуждении, а в
самой схеме: `Dimension.scores` это `dict[str, int | float | str]`, то есть
произвольные ключи с union-значениями. Такая грамматика на порядок дороже плоской
схемы синтеза. Побочный вывод для doc 16: **схема под constrained decoding должна
быть плоской**, иначе она не ускоряет, а срывает таймаут (это же объясняет часть
известного хвоста «synth-таймаут 300 s»).

- [ ] D1.1: непроверенная клетка — `think:false` **без** схемы на compare. Потолок
      −30…−40 % от 205 s (≈ 7 % сессии). Критерий тот же: winner, порядок rankings,
      размерности.
