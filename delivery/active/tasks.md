# Tasks — sitemap-index (как агент будет «нормально искать»)

**Вопрос владельца:** поиска по сайту у агента нет — надо внедрять? Ответ получен замером,
и он оказался другим: **поиск по сайту на этих порталах не работает, а sitemap работает —
просто он был сломан ровно той же ошибкой, что мы чинили дважды.**

Журнал: [doc 26 § T-3j](../../docs/26-real-site-trials.md).

## Почему поиск по сайту отклонён (замер, а не мнение)

- [x] **E1** `sports.ru` — поиск есть, но `robots.txt` содержит `Disallow: /search/`.
      Инвариант проекта robots соблюдать → ход недоступен **по правилам**, а не по технике.
- [x] **E2** `championat.com` — эндпоинта поиска нет: восемь распространённых шаблонов дают
      404 либо возвращают **главную страницу** (0 новых ссылок против главной).
- [x] **E3** `legalbet.ru` — страница поиска есть, но **параметр URL игнорируется**: в тексте
      «Ничего не найдено по запросу «»» при любом запросе, обе выдачи побайтово одинаковы.
      Поле спрятано за кнопкой и заполняется JS.
- [x] **E4** общий вывод: работающий вариант — **печатать в поле и жать «Найти»**, а это по
      doc 25 **Tier 2** (submit под подтверждением человека). Для автономного обхода
      непригодно без отдельного решения владельца «submit поиска — read-only Tier 1».
      Решение не принимал: это канон безопасности.

## Что вместо этого починено (sitemap уже был, но не работал)

- [x] **E5** **вложенные карты брались по порядку**: у `legalbet.ru` в индексе 30 карт, нужная
      `sm_shkola_bettinga.xml` — **22-я**, а брались первые три (`sm_best_posts`, `sm_bonus`,
      `sm_bonus_compilation`). Теперь выбор **по имени**: слова задачи (с транслитом), словарь
      обучающего жанра, слуги интента.
- [x] **E6** **карты сущностей топили обход**: у `championat.com` первая же карта `stats.xml`
      ведёт к **5385** вложенным картам статистики. Такие имена (`stat`, `match`, `team`,
      `tag`, `video`, `player`, `amp`) пропускаются.
- [x] **E7** **ранжирование URL шло русскими словами против латинских путей** — та же дыра,
      что чинили в оценке ссылок: `/shkola-bettinga/stavki-na-futbol` не совпадал **никогда**,
      и весь tier для русских задач молча давал ноль.
- [x] **E8** замер на живых сайтах: `legalbet.ru` **0 → 20 кандидатов**, все из школы
      беттинга (`stavki-na-futbol-v-bk-*`), за один HTTP-хоп от robots.txt. `sports.ru` — 0
      (сайт не объявляет sitemap вовсе), `championat.com` — 0 (обучающих статей там нет,
      что согласуется с ручной проверкой).
- [x] **E9** гейты: 411 тестов, ruff, format, mypy strict, размер модулей.

**Не в этой поставке:** поиск по сайту через заполнение поля (нужно решение владельца по
тиру); `article` пустой при `content_search`; `think:false` без схемы на `compare`; зрение
навигации; вынос `check_docs_index.py`.

## Правило владельца: «умнее вообще, а не под сайт» (T-3k)

- [x] **E10** прогон при новой глубине (`b2da3d167eee`) — **лучший результат серии**: на
      `legalbet.ru` статья найдена (1380 слов, 6 разделов), второй кандидат отклонён с
      причиной, победитель с цитатой; `sports.ru` дошёл до вики первым ходом; `championat`
      честно «нет статей».
- [x] **E11** аудит собственных правок: два словаря оказались **вертикальными** —
      `promo_markers` (ставки) и «мусорные карты» sitemap (спорт). **Удалены по замеру:**
      без них хаб #1, эталон #1, championat #10, вики #4, доля тематических не упала нигде.
- [x] **E12** вместо словарей — общее правило: до **2** добавляющих слотов под разделы,
      которых в окне по счёту нет вовсе («десять образцов с одной полки» бывает и в
      магазине, и в новостях).
- [x] **E13** более сильный вариант (обход по кругу разделам) **отклонён замером**: ширина
      ценой тематичности, 10/10 → 4/10 на `championat.com/bets/`.
- [x] **E14** предел очереди зафиксирован явно: 10 по счёту + ≤4 подраздела + ≤2 незнакомых
      раздела = **≤16**; старый тест на «ровно 10» обновлён осознанно.
- [x] **E15** гейты: 412 тестов, ruff, format, mypy strict, размер модулей.

**Граница, названная честно:** общее правило не делает счёт умнее — на синтетике «голый»
раздел всё ещё проигрывает рекламной записи по форме (45 против 49). Оно лишь не даёт одной
полке занять весь обзор, а выбор остаётся за моделью.
