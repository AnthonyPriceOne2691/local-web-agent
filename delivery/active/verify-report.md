## Что проверялось

Хук `protect_main` должен блокировать переписывание истории main и **не** мешать
обычной работе. До правки он проверял правила по всей строке команды, поэтому
признаки складывались из разных мест.

## Оба направления, а не только «стало зелено»

| Направление | Как проверено | Результат |
|---|---|---|
| Опасное блокируется | 13 кейсов «должен заблокировать» | ✅ exit 2 у всех |
| Безопасное проходит | 12 кейсов «должен пропустить» | ✅ exit 0 у всех |
| Сообщение доходит до агента | `blocked:` в stderr | ✅ |
| Битое/чужое событие не мешает работе | 5 payload'ов, включая не-JSON | ✅ exit 0 |

Тесты вызывают хук **процессом** и кормят его stdin-JSON: проверяется настоящая
граница (разбор события + exit code), а не внутренняя функция.

## Негативный контроль (без него проверка пустая)

`PROTECT_MAIN_HOOK=<версия из origin/main> pytest tests/test_protect_main_hook.py`
→ **4 падения**:

- `git push --force origin fix/protect-main-segments` — ложный блок (слово `main`
  внутри имени ветки),
- `git push --force origin fix/main-guard` — то же,
- `git push origin fix/a && pkill -f "uvicorn app.main:app"` — ложный блок
  (признаки из двух разных команд),
- `git reset --hard upstream/master` — **пропуск опасного**: старое правило знало
  только `origin/`.

То есть новая версия не «мягче», а строго точнее: три ложных блока убраны, одна
настоящая дыра закрыта.

## Честные ограничения

- Сегментация по `&&`/`||`/`;`/`|`/переводу строки — **эвристика**: кавычки,
  подстановки и here-doc не разбираются. Ошибается она в сторону блокировки
  (нераспознанный разделитель оставляет два фрагмента одним сегментом).
- Ветка вида `feature/main` будет принята за защищённую — тоже сознательно в
  безопасную сторону.
- Хук **не заменяет** серверную защиту ветки (платная на приватном репо, остаток
  в `delivery/STACK-ACCEPTANCE.md` § Остатки). Он поднимает цену случайности.
- Тесты хука не проверяют, что Claude Code действительно вызывает его как
  PreToolUse: это конфигурация `.claude/settings.json`, проверенная вживую
  (блок сработал в этой же сессии на попытке отключить хуки при коммите).
